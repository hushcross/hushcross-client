# Android shell dependencies

This hand-authored TWA configuration follows the documented Android Browser Helper integration and references Bubblewrap's Apache-2.0 templates. It was not generated by running the Bubblewrap CLI.

- Bubblewrap template reference: GoogleChromeLabs/bubblewrap **v1.27.0**, commit `0eb0671985d3f28eb2567a5463999046255fa3b8`. Copyright 2019–2020 Google Inc. [Template sources](https://github.com/GoogleChromeLabs/bubblewrap/tree/0eb0671985d3f28eb2567a5463999046255fa3b8/packages/core/template_project). [Apache-2.0](licenses/Apache-2.0.txt).
- Runtime: `com.google.androidbrowserhelper:androidbrowserhelper:2.7.4`, Apache-2.0. [Official source](https://github.com/GoogleChrome/android-browser-helper), [published POM](https://dl.google.com/dl/android/maven2/com/google/androidbrowserhelper/androidbrowserhelper/2.7.4/androidbrowserhelper-2.7.4.pom).
- Android Gradle Plugin: `com.android.application:8.13.0`, using the installed Gradle **8.14.3**, JDK **21**, SDK **36**, Build Tools **35.0.0**. [Compatibility](https://developer.android.com/build/releases/agp-8-13-0-release-notes).

The runtime POM declares AndroidX annotation 1.9.1, core 1.17.0, appcompat 1.7.0, browser 1.10.0, Guava 33.4.8-android, Kotlin BOM 1.8.22 and coroutines BOM 1.7.3. Transitive components retain their original licenses. Dependencies resolve only through Google Maven and Maven Central; this project adds no package registry or install hook.

Local configuration deliberately differs from the reference: no notification delegation, native WebView fallback, billing, location delegation, analytics, signing configuration or key-handling code. The launcher accepts only the canonical HTTPS origin. Build tooling is reused rather than installed by the generator.
